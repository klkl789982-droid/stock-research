# 상승 전환 근거 연구 v1

`transition-evidence-research-v1`은 기존 교차 판정과 접근 강도, A/B/C/D 점수와 독립적이다. 확률·기대수익률·매수 추천이 아니다. 초기 설정은 탐색 가설이며 성과에 맞춘 사후 조정은 하지 않는다.

## 판정 계약

설정은 `lib/transition-evidence-policy.mjs`에 한곳에서 관리하고 canonical SHA256으로 식별한다. 필요한 값이 없으면 해당 근거는 `DATA_MISSING`; `MET`만 충족 수에 포함한다. 부분 충족과 미충족, 결측은 별개다.

| 근거 | 충족 | 부분 충족 |
| --- | --- | --- |
| 간격 | 단기선이 장기선 아래에서 최근 3거래일 연속 절대 간격 축소 | 당일만 축소하거나 연속성이 부족 |
| 단기 추세 | 단기선 기울기 > 0 및 직전 기울기 대비 개선 > 0 | 아직 하락하지만 둔화, 또는 상승 중이지만 가속하지 않음 |
| 모멘텀 | RSI14 변화 > 0 및 MACD 히스토그램 변화 > 0 | 둘 중 하나만 개선 |
| 거래량 | 종가 상승 > 0, 당일 포함 20일 평균 대비 >= 1.2배, 전일 대비 거래량 증가 > 0 | 상승 종가와 거래량 조건 하나만 충족 |

단기선이 이미 장기선 이상이면 **간격 접근 근거는 미충족**이다. 교차 발생/확인 상태가 별도로 남으므로 이미 교차한 종목의 추세 개선을 숨기지 않는다. 네 근거 수가 낮다고 약세·매도 신호로 해석하지 않는다. 이미 상승 중인 종목의 개선도 검출되므로 이전 하락 추세에서의 반전만을 보장하지 않는다.

RSI·MACD 변화는 기존 `calculateTechnicalModelFeatures`를 재사용하며 현재 값은 기존 market-analysis 계산과 수치 일치를 테스트한다. MACD/Signal 관계는 표시 정보이지 모멘텀 개선의 필수 조건이 아니다. 보조 돌파는 현재 종가가 **당일을 제외한 직전 20거래일 고가**보다 높은지 확인한다. 돌파는 네 근거 수와 프리셋 필수 조건에 포함하지 않는다.

## 필터와 프리셋

기존 `/api/screener?tab=transition` 및 관리자 서버 인증을 사용한다. `trendEvidence`, `momentumEvidence`, `volumeEvidence` = `all|improving|met`; improving은 충족 또는 부분 충족. `evidenceMin=0..4`는 네 근거 모두 평가 가능한 종목에만 적용한다. 결측 제외는 기존 `filterMissing`으로 구분한다. `state=CROSSED_OR_CONFIRMED`는 두 상태의 합집합이다.

- 초기: 골든 접근, 5/20, 접근 강도 내림차순, 추세·모멘텀 충족/부분 충족.
- 확인: 골든 발생/확인, 5/20, 추세 충족/부분 충족, 거래량은 결과에서 확인.
- 강한 초기: 교차 상태 무관, 모멘텀 충족/부분 충족 + 상승 거래량 충족. 교차 미발생도 포함한다.

프리셋은 조건을 초기화해 적용한 뒤 사용자가 수정할 수 있다. AND 조건은 그대로 유지한다. 근거 수 정렬은 평가 가능 수별로 분리(4개, 3개, …)하여 결측 그룹을 뒤로 두고 각 그룹 안에서 충족 수를 정렬한다. 간격 축소 속도는 장기선 아래 두 연속 관측의 절대 간격 변화(%p), 거래량 증가순은 전일 대비 변화율이다.

## 재현 및 미래 성과

공식 history/seed/calendar의 기존 검증을 먼저 통과한 입력만 사용한다. KIS·장중·LIVE 데이터는 사용하지 않는다. 최신 seed가 없으면 과거 결과를 최신인 것처럼 반환하지 않는다. 파일 변경과 설정 hash로 계산 캐시를 무효화하고 동시 요청은 공유한다.

`createEvidenceObservationSnapshot`은 별도 `transition-evidence-signals` 계약을 생성한다. 신호일·종목·조합·골든/데드 방향·기존 상태/접근 강도·네 근거 수치·설정과 hash·입력 seed hash·기준일 및 contentHash를 보존한다. 관측 ID에는 버전·설정·입력 hash를 포함한다. 기존 v1 snapshot 및 hash는 변하지 않는다. 영구 저장을 연결할 때 동일 ID create-only/hash 재검증을 사용해야 하며 기존 관측을 재작성하지 않는다. GET 조회는 파일을 쓰지 않는다.

향후 `transition-evidence-outcomes`의 1D/5D/20D에 연결할 수 있지만 현재는 `NOT_OBSERVED`, 진입 계약은 null이다. 자동 연구 신호 저장·체결 계약·미래 수익률 계산은 이번 단계에서 활성화하지 않는다. 성과 표본이나 확률을 만들지 않는다.
